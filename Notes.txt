Dapper
| Method                        | Purpose                  | Example                         |
| ----------------------------- | ------------------------ | ------------------------------- |
| `QueryAsync<T>`               | Get multiple rows        | `SELECT * FROM Jobs`            |
| `QueryFirstAsync<T>`          | Get one row              | `SELECT * FROM Jobs WHERE Id=1` |
| `QueryFirstOrDefaultAsync<T>` | Get one row or null      | search by id/name               |
| `ExecuteAsync`                | INSERT / UPDATE / DELETE | `UPDATE Jobs SET...`            |
| `ExecuteScalarAsync<T>`       | Get single value         | `COUNT`, `EXISTS`, `SUM`        |


| Area              | What to do                                             |
| ----------------- | ------------------------------------------------------ |
| Querying          | Select only needed columns, not `SELECT *`             |
| Paging            | Load 50–100 rows first, not everything                 |
| UI                | Keep virtualized `ListBox`, no external `ScrollViewer` |
| UI loading        | Keep batched insertion with `Chunk(25)`                |
| SQL               | Use `JOIN`s instead of LINQ lookups inside loops       |
| Sorting/filtering | Do it in SQL, not in memory                            |
| Cards             | Avoid shadows/gradients on every card                  |
| Refreshing        | Refresh only changed item, not whole dashboard         |
| DB writes         | Wrap multiple inserts/updates in a transaction         |
| Dates/prices      | Store clean values, format only in UI                  |
| Diagnostics       | Use `EXPLAIN QUERY PLAN` to check if indexes are used  |
